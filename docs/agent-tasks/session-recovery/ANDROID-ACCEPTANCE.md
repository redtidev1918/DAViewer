## 安装与测试顺序

1. 直接覆盖安装新 APK。不要卸载、清除数据或清除 Cookie。包名是
   `app.daviewer`，使用与正式 v0.5.13 相同的签名。
2. 先检查当前账号状态。如果已退出，完成一次登录：网站授权后应自动返回
   应用首页，账号信息更新，推荐页出现真实个性化数据。网站首页本身不是
   应用 OAuth 登录完成的证据。若失败，立即导出日志并停止重复尝试。
3. 登录成功后，另行验收“保留登录冷启动”：系统设置中强制停止，再打开
   应用，直接查看推荐页，不进入登录页、不重新登录。首次失败立即导出；
   首次成功才继续，共 10 次。已有缓存显示不等于实时推荐请求成功。
4. 再测试前后台切换、手动刷新、网络/代理断开后恢复。保留原代理设置，
   记录操作时间、设备型号、Android 和系统 WebView 版本、每项结果。
   退出后重新登录与保留登录冷启动分别记录 PASS/FAIL/PENDING。

任何失败都优先导出当前证据，不需要通过反复登录或重复失败测试收集次数。
模拟器或自动化测试不能代替原故障手机的证据。

## 导出最近 20 次启动日志

打开 **设置 → 日志与诊断**，点击顶部的**向上箭头导出图标**，其提示文字
为 `Export recent launch logs (20)`，在系统分享界面保存/发送
`DAViewer-cold-start-logs.txt`。登录界面右上角的设置入口也可进入诊断。

请提供这个导出文件，附上失败操作时间。页面预览只显示当前日志的最近
120 行；“报告问题”生成的摘要也不是跨启动完整日志。

导出按时间排列，最多包含最近 20 个启动文件（旧版和新版合计），每个文件
最多保留末尾 512 KiB，截断会明确标记。开头的 `sessions=N` 与每个
`=== launch ... ===` 可核对数量；每次启动的 `buildRevision` 可区分同为
v0.5.13 的不同候选构建。导出会等待已排队写入并脱敏，强停仍可能丢失最后
一个尚未落盘事件。不要为了凑满次数重复一个已失败的登录流程。

## 可选 ADB 冷启动助手

USB 调试授权后先运行 `D:\Android\Sdk\platform-tools\adb.exe devices -l`，
确认目标设备序列号，然后在仓库运行：

```powershell
pwsh -File scripts/android-session-recovery.ps1 -Serial '设备序列号' -Count 10
```

脚本只操作明确指定的设备；默认首次失败/待确认就停止。每次等待观察后，
由你输入 PASS/FAIL/PENDING，记录到本机 CSV。它不会替你判断屏幕是否正确。
可用 `-WhatIf` 预览命令。它不安装 APK、不退出登录、不清数据、不清 logcat、
不修改代理；请先自行覆盖安装并确认一次登录成功。

脚本保存的结果是操作记录；**最终仍导出应用的跨启动日志**。发行版应用
私有目录不能在普通未 root 的手机上直接用 adb pull/run-as 读取，不需要
解锁或 root 手机。提交序列号等个人设备信息前可自行删除。

## 本机日志整理

```powershell
D:\flutter-sdk\bin\dart.bat run scripts/summarize-session-recovery.dart --input '导出文件路径' --output '新的整理目录'
```

输出脱敏文本和 JSON：按启动/请求列出阶段、物理传输数、终态和缺失终态。
它只整理证据，不自动授予 Android Verified 或 Original Incident Verified。
旧候选日志可能缺少字段或终态，此时应保留缺失标记，而不是推断成功。
