# REG-017 网页身份健康压制推荐降级提醒

用户要求从系统上解决通用内容出现在推荐页却没有更新 Cookie 提醒的问题。

REG-016 补上了请求前的身份验证，但身份健康并不证明推荐接口可用。REG-009 曾
记录 `vespa_content_group: 2` 游标出现在通用回退中，之前没有代码消费这一信号。
SDK 映射后的作品列表仍可直接进入缓存，后续首页用户名确认也没有推荐降级状态可保留。

新增 `personalizedSessionStatusProvider`，与 `webSessionStatusProvider` 分开：

| 网页身份 | 推荐响应 | 行为 |
|---|---|---|
| 未确认或验证受阻 | 不请求 | 显示无法确认，网络故障不判断为登出 |
| 确认匿名 | 不请求 | 显示登录恢复入口 |
| 确认登录 | 历史 group 2 回退信号 | 丢弃响应，记录疑似降级，提供登录和重试入口 |
| 确认登录 | 未出现已知降级信号 | 接受响应；这不证明算法必然个性化 |

推荐降级提醒不会因周期首页确认而消失，关闭后也不会每次首页确认就重复弹出。
显式登录恢复产生新代际；导入 Cookie 重置推荐状态并作废推荐 Provider；重试取得
未出现已知降级信号的响应也可解除提醒。随后再次降级可以再次提示。

已接受响应的 Cookie 指纹与推荐状态一起保存，后续 Cookie 变化会强制复核。完成
请求时再次比对 Cookie 和登录代际，拒绝轮换期间或同账号重新登录前启动的旧结果。
日志记录状态、来源、代际和指纹，不输出 Cookie 值或 CSRF。

测试覆盖：身份验证成功但 group 2 响应仍被拒绝；登录恢复后重试；Cookie 改变强制
复核；同账号新登录及在途 Cookie 轮换丢弃旧结果；未知游标不当成回退；降级提示
出现、关闭、身份复核保持关闭，以及恢复后的新降级再次提醒。

group 2 是历史证据中的疑似回退信号，并非已验证的 DeviantArt 全部推荐协议。
没有读取用户当前 Cookie，也没有取得当前推荐原始响应；不能承诺所有通用回退都
带此游标，或凭作品题材区分通用和个性化。真实会话及私有协议变化仍需实机证据。
